# QQBot 群监测 — 实现说明

把 QQ 群成员身份与 new-api（`https://api.fuzy.site`，系统名 FuZY）账号关联起来的监测服务。
只读群、不发消息（唯一例外：响应成员发来的 `>>绑定<<`）。设计共识见 `docs/design-notes.md`
与 `docs/adr/`；本文件记录**已实现**的形态与验证结果。

## 运行

```bash
cd /home/QQbot
go build -o qqbot ./cmd/qqbot
./qqbot -addr :4096 -data data -web web/dist
```

监听地址也可由 `.env` 的 `QQBOT_PORT` 指定（见下）；显式 `-addr` 参数优先。

前端（改了 `web/` 才需要）：

```bash
cd web && npm install && npm run build
```

首次打开 `http://<host>:4096/` 会要求设置管理账号（本项目自己的账号，与 new-api 无关）。
之后同一表单用于登录。

管理账号也可以**从环境变量预置**，适合部署时无人值守：在**仓库根目录**放 `.env`（与
`.env.example` 同级；也可用 `QQBOT_ENV_FILE` 指定别的路径），写入
`QQBOT_ADMIN_USERNAME` / `QQBOT_ADMIN_PASSWORD`，启动时在服务器开始接受请求**之前**读取，
因此新实例不会有一瞬间对先到者敞开。进程环境变量优先于文件，容器/systemd 可覆盖文件而不改它。
密码留空视为「不改动已有账号」，所以模板里的空行不会把面板唯一的门清掉；改密码并重启即重置
（密码丢失时的恢复路径）。

同一个文件里用 `QQBOT_PORT` 配置**面板监听端口**（可写裸端口 `4096`，也可写完整地址
`:4096` / `127.0.0.1:4096`）。优先级：显式 `-addr` 参数 > 环境变量 > 默认 `:4096`。

```bash
# .env（仓库根目录）
QQBOT_ADMIN_USERNAME=admin
QQBOT_ADMIN_PASSWORD=至少8位
QQBOT_PORT=4096
```

## 数据与配置

**全部状态都在 `-data` 指定的目录里**（默认 `data/`），备份或迁移只需搬这一个目录：

| 文件 | 内容 |
|---|---|
| `data/qqbot.db` | 监测群、成员、绑定、签到、分组转换规则、监测设置、管理账号、会话签名密钥、new-api 账号缓存 |
| `data/config.yaml` | new-api 与 NapCat 的连接配置（权限 0600） |
| `.env`（仓库根目录） | 可选：管理账号与监听端口的环境变量预置（权限 0600，见上）。不进版本库 |

`config.yaml` 与 WebUI 的「连接配置」是**同一份配置**，两种改法都有效且不会互相覆盖：

- 手改 `config.yaml` 并保存 → 服务在**下一次读取时**采用，**不需要重启**；语法错误只报错并
  继续用数据库里的旧值，不会把可用配置写坏。
- 在 WebUI 保存 → 同时写入数据库与该文件。
- 文件不存在时自动创建（内容取自数据库），两种方式都能作为起点。
- 文件中密码/token 是**明文**（否则无法回写），故权限设为 `0600`。

「连接配置」页面分成**两张独立的卡**：**new-api 管理员账号**与 **NapCat**，各自保存、各有
自己的 revision（`GET /api/config` 返回 `revisions.{newapi,napcat}`）。保存一半不会动另一半，
半填的表单也不会互相阻塞（见 ADR-0008）。

## 结构

| 包 | 职责 |
|---|---|
| `cmd/qqbot` | 入口、参数、按需重建的网关/NapCat 客户端 |
| `internal/store` | SQLite 表结构、迁移、查询 |
| `internal/service` | 业务逻辑（同步/绑定/分组转换/发奖），只依赖 `Gateway`、`QQ` 两个接口 |
| `internal/command` | 指令解析与匹配（字面量 + `/正则/`） |
| `internal/newapi` | new-api 管理接口客户端 |
| `internal/napcat` | OneBot HTTP 客户端 + NapCat WebUI 桥 |
| `internal/events` | OneBot WebSocket 监听（指令、进群、消息签到） |
| `internal/api` | HTTP 接口、鉴权、静态文件 |
| `internal/config` | 连接配置（文件 + 数据库双份） |
| `internal/scheduler` | 按路径拆分的独立巡检 |
| `web/src/features` | 面板按功能拆分的模块（设置页每块一个开关） |

## 已实现的行为

- **群管理**：从 QQ 读取机器人账号所在的群，用开关勾选要监测的群；**新发现的群默认不监测**，
  需要手动打开（机器人可能被拉进无关的群，而监测一个群意味着记录其成员并发放奖励）。
- **分组转换（规则）**：管理员在「分组转换」菜单里配置规则 —— 触发方式（**复选框**：绑定成功时 / 巡检
  周期分钟数，可同时勾选）、源分组（可多选，从 new-api 拉取，留空 = 任意）、目标分组（从 new-api
  拉取或手填）、以及可选条件（群等级、QQ 等级、入群天数、累计签到天数、new-api 余额、
  new-api 请求数，条件之间是「且」）。规则在**绑定成功时**（巡检自动匹配、进群绑定、
  绑定指令、管理员手动绑定四条路径都会触发）和**各自的巡检周期**执行。既无触发方式又无
  条件的规则视为未完成，不匹配任何人。删除规则前弹确认框，写明规则名与「不再执行分组转换」。
- **成员同步**：成员以 QQ 为主键；群关系存在 `member_groups`，成员退出某个群不会删成员行，
  绑定与签到历史得以保留。
- **自动绑定（巡检）**：用 `qq@qq.com` 查 new-api，**精确且唯一**才绑定；0 个 → 未绑定；
  多个 → 不绑定并计数。未绑定的成员按自己的周期重试（默认 60 分钟，账号可能后建）。
- **进群自动绑定**：`group_increase` 事件到达时按同一规则立即匹配；成员先被记录，再尝试绑定，
  因此绑定失败不会让人从名册里消失。
- **绑定指令**：成员在监测群发指令（默认 `/绑定`、`<绑定>`、`>>绑定<<`，可在设置里改成任意
  多条、支持正则）即绑定到 `他的QQ@qq.com` 对应账号；不接受指定别的邮箱。经 OneBot
  WebSocket 事件触发；事件通道不可用不影响其它功能。
- **三条自动绑定路径共用 `bindQQ`**：遇到已有绑定一律跳过，所以打开任一开关都不会覆盖
  手动换绑的结果。三条的区别只在触发方式，以及「查不到账号」的语义（巡检计入 pending、
  进群不算失败、指令报错）。
- **手动换绑**：WebUI 用户管理里可把任意 QQ 改指到任意 new-api 账号，也可解绑。绑定弹窗
  **两侧都是下拉选择**（QQ 从群成员里选，账号从已同步的账号里选），因此**从任一侧都能发起**：
  一个未绑定的成员可以挑账号，一个没人进群的账号也可以挑 QQ（旧版只能从 QQ 侧发起，从账号侧
  发起会因 `qq` 为空被拒）。账号的用户名与邮箱在未提供时**从账号缓存补全**，避免存下空邮箱
  （空邮箱的绑定再也无法与 `qq@qq.com` 匹配）。**解绑前弹确认框**：写明 QQ、对应账号，以及
  「绑定方式（source）会一并丢失、无法撤销」——重新绑定只能得到 `auto`，手工挑选的账号与来源
  无法复原。两个破坏性操作（解绑 / 删除规则）共用同一个确认组件，处理期间两个按钮都禁用，
  双击不会触发两次。
- **用户管理（用户目录）**：以 **QQ 与 new-api 账号两个键**取并集，回答「谁没进群」：
  - 每一行是一个在群成员、一个已退群成员，或一个**没有任何 QQ 对应的 new-api 账号**
    （标「未进群」）。绑定到某个 QQ 的账号即使没有成员行也不会消失。
  - 账号缓存来自 `POST /api/users/sync`（读 new-api 的账号列表，整表替换）；未同步时表格
    仍可用，只是看不到「未进群」的账号。
  - 支持按**绑定状态 / 群状态 / 分组 / 类型 / 关键词**筛选；关键词匹配 QQ、昵称、new-api
    用户名与邮箱。
  - **显示分组**并可**逐行调整**（下拉即改），也可**勾选多行批量调整**到同一分组。写入前
    按 id 重读账号（new-api 的更新是覆盖式的），已是目标分组则不发请求；批量时每个账号单独
    报告结果，个别账号无权限不会拖累其余。
- **签到**：两条来源写同一行 `(qq, 日期)`：
  - **打卡榜巡检**：轮询 `get_group_signed_list`（榜单只含当日且分页，多轮结果是**并集**），
    写入 `source=board`，带排名与打卡时间；
  - **消息签到**：群消息触发，写入 `source=message`。指令列表非空时只认列出的指令；
    **留空表示任意消息**。重复消息不会重复记录。
  打卡榜后到会**升级**消息来源那行（它知道得更多），消息后到则不覆盖任何字段。累计天数即
  `checkins` 的行数。用户管理表格显示今日签到的来源（打卡榜 / 消息）。
- **发奖**：每天每人一次，额度（单位 new-api 的 **quota**，`add_quota` 直接加到账号余额）在
  `[下限, 上限]` 内随机；发放前先把金额落库，用
  `rewarded_at` 占位，网关失败才释放重试，成功则永不重发。两条签到来源都不碰
  `reward_quota` / `rewarded_at`，所以「任意消息」不会变成一天多次奖励。
- **巡检**：成员列表、绑定、打卡榜、分组转换规则各自独立周期（默认 120 / 60 / 30 分钟，
  规则按最短配置周期），每次循环重新读取配置，改设置无需重启。启动后延迟 20 秒再跑首轮。
  **间隔的 0 只在绑定巡检表示「暂停定时」**（服务端保留该 0）；群成员巡检与打卡榜巡检的 0
  会被服务端修复为默认值（0 分钟的循环没有意义），所以面板对这两行强制最小 1，只有绑定巡检
  允许 0。签到循环的间隔不靠 0 暂停——它同时负责发奖，只要有任一条签到路径开着就必须继续跑。
  `GET /api/status` 返回每条巡检的上次运行时间与错误，连同设置一起返回——只看时间无法区分
  「还没跑」与「已停用」。
- **关掉的功能不产生请求**：每条巡检按自己的开关跳过，且最贵的调用在调用点再判一次——
  打卡榜巡检关闭时不读榜单（发奖照常，因为发奖与读榜是两件事）；一批规则里若没有 QQ 侧
  条件（群等级/QQ 等级/入群天数），就不读任何群成员列表。绑定路径上这条最值钱：`AutoBind`
  每绑一个人都会跑一次绑定规则。
- **一次巡检只读一遍成员列表**：`qqDataCache` 在整次绑定巡检内共享，每个监测群读一次。
  实测 6 人 × 3 群 = 3 次 `get_group_member_list`（修复前是 18 次）。缓存在 `contextFor`
  里按需加载，避免「忘了预热 → 所有 QQ 侧条件静默 fail closed」。
- **多群成员的取值各路径一致**：`mergeContext` 对 群等级/QQ 等级/入群天数 逐字段取最大值，
  绑定触发与巡检不会因为读取顺序不同而给出不同结果。
- **鉴权**：除 `/api/auth/{state,setup,login,logout}` 外全部接口需要登录会话。管理账号可在
  首次运行表单创建，或由环境变量（`data/.env` / 进程环境）在启动时预置；改环境变量并重启即
  重置密码（丢失时的恢复路径）。
- **连接配置（分区块 + 自动配置）**：new-api 与 NapCat 两张卡各自保存、各有 revision，保存
  一半不动另一半。NapCat 卡提供「自动配置」：只填 WebUI 地址与 Token，服务登录 NapCat 后
  自动开启 OneBot 的 HTTP 与 WebSocket 适配器（热改，无需重启），并把 OneBot / 事件地址与
  token 回填；重复执行幂等，且不碰操作者自己的适配器（见 ADR-0008）。
- **连接测试**：两张卡各有「测试连接」，用表单里当前的值（密码/Token 留空或为 `********`
  时用已存值）**按通道分别探测**并逐条报告结果与原因：
  - new-api：登录并回读 `/api/user/self`，显示账号、id、role、分组——「能连上」不够，要看到
    **连的是哪个账号**。
  - NapCat：WebUI 登录、OneBot HTTP 的 `get_login_info`、事件 WebSocket 各一条。未配置的
    通道标「跳过」而非「失败」；WebUI 能登录但 QQ 未登录时算部分成功并说明原因。
  - 测试只读、不改任何配置，也不影响正在运行客户端已缓存的会话。

## 验证方式

- `go test ./internal/...` —— 全离线，两个外部系统都用假实现；`go test -race ./internal/...`
  也是干净的。
- 真实联调（手动，不放进 `go test`）：
  - `POST /api/groups/refresh` 读到真实群 `1129535731`；`POST /api/actions/sync` → 3 名成员；
  - 分组转换把测试账号从 `default` 提到 `authorized`，`display_name` 保留，已还原；
  - `POST /api/actions/award` 真发额度（在区间内），重复执行不重发，已回滚；
  - 浏览器实测首次设置、登录、各页面渲染、`>>绑定<<` 经真实 WebSocket 触发；
  - 配置持久化：首次启动生成 `config.yaml`；手改文件后**不重启**即生效（NapCat 侧随即可用）；
    WebUI 保存会重写文件且密钥不丢；重启后成员/绑定/规则/设置/会话全部保留。
  - 模块化绑定/签到（ADR-0009）：用一个本地 WebSocket 服务回放 NapCat 的事件 JSON，验证
    `group_increase` 记录并进群绑定、指令消息绑定、消息签到只认指令（普通消息不算）、
    同一天第二次签到是 no-op、`/api/actions/checkin-member` 与状态接口；再对真实网关验证
    自动绑定（命中 `qq@qq.com` 的账号）与真实发奖（`awarded: 1`，重复执行 0），随后还原。
    指令正则非法时 `POST /api/settings` 返回 400 且不改动已存配置。
- 已知边界：**管理员账号不能管理同级或更高级账号**。用 `napcat`（role 10）去改组/发额度到
  它自己（也是 role 10）会被拒 —— 这是 new-api 的规则，不是缺陷。验证时请用普通账号（role 1）。
- **new-api 有活跃会话上限（默认 50，有效期 30 天）**，但本服务不会自己把它用满：访问令牌只活
  15 分钟而登录会话活 30 天，所以令牌到期时**刷新会话**（`POST /api/user/auth/refresh`，随登录
  下发的 `new_api_refresh` HttpOnly cookie 续期），而不是重新登录。额度被占满时登录返回
  `AUTH_SESSION_LIMIT`，面板提示「请撤销其他登录会话或等待其过期」。
- **登录接口有频率限制**（`CRITICAL_RATE_LIMIT`，默认每 IP 每 20 分钟 20 次）。被限流时网关
  返回**空 body 的 429** 与 `Retry-After`；客户端按状态码识别、把等待时间写进错误信息，并用
  `newapi.Lockout` 在窗口内拒绝再次尝试 —— 盲目重试只会让锁定期越拖越长。

## 尚未实现 / 需注意

- 打卡榜的 `rank` 是 NapCat 换算过的值（`(signInRank-1)/2+1`），只作展示，不要当稳定标识。
- **消息签到依赖事件流**：事件 WebSocket 断开时消息签到不会记录，打卡榜巡检与发奖不受影响。
  「任意消息」模式下事件流长期不可用会表现为签到偏少，而不是报错。
- NapCat WebUI 凭证在 NapCat 重启后失效（除非设了 `NAPCAT_WEBUI_JWT_SECRET_KEY`），
  本服务会重登，注意登录频率限制。
- NapCat 的 QQ 登录态会过期（`登录态已失效，请重新登录`），此时 OneBot 适配器不启动，
  任何 QQ 侧读取都会失败；需要重新扫码登录。这与本服务无关，但会让巡检持续报错。
- 规则引擎的实盘端到端验证（绑定 → 自动转换）因 new-api 会话额度耗尽而**未完成**，目前只有
  单元测试覆盖；恢复凭据后应补一次。
