# 0007 用户目录以 QQ 与 new-api 账号双键取并集

用户管理页不再只列「群成员」，而是把 **QQ 成员** 与 **new-api 账号** 两侧都列出来，每行同时
携带另一侧的键（若存在）。目的是回答运营问题「谁没进群」：注册了账号但从未加入 QQ 群的人，
必须出现在表里。

## 为什么是并集，而不是只列成员

只列 `members` 表会漏掉两类人：

- **未进群账号**：new-api 上有账号、有邮箱，但没有任何 QQ 成员行。这正是要排查的对象。
- **绑定存在但成员行缺失**：手动换绑接受任意 QQ（见 ADR-0002 的三条绑定路径），可以绑到一个
  从未被成员巡检记录过的 QQ。此时只按成员行出表会让这个**已绑定**的账号凭空消失。因此账号
  循环只在「成员行已经展示过该账号」时才跳过它。

行有 `kind`：`member`（在群）、`left`（已知 QQ 但已不在任何监测群）、`account`（无 QQ 的
账号）。「已退群」与「未进群」是不同的问题，所以分开标。

## 账号侧是缓存，整表替换

new-api 的账号列表通过 `GET /api/user/` 分页读取（不是 `/search`：那是关键词 LIKE，空关键词
不保证「全部」）。结果整表替换进 `newapi_users`，因为网关是账号的真相来源 —— 在网关侧被删除
的账号不能在缓存里阴魂不散，继续显示成「未进群」。

**代价**：整表替换意味着只能在**完整读取之后**才写。任何一次部分读取都会删掉它没读到的账号。
所以客户端在分页出错时直接返回错误，而不是返回「读到的部分」；调用方也只有拿到完整列表才
替换缓存。

## 调整分组

- 写入前**按 id 重读账号**，理由与分组转换相同（ADR-0005）：new-api 的 `PUT /api/user/` 是
  覆盖式的，稀疏对象会清空 `display_name`。
- 账号已在目标分组时不发请求（网关侧是无谓写，且重读可能拿到稀疏对象）。
- 批量调整**逐个账号报告结果**：new-api 不允许管理员操作同级或更高角色的账号（见 AGENTS.md
  的坑），一个这样的账号不应该让整批选择失败。

## 被否决的替代方案

- **只列成员 + 单独一页「未绑定账号」**：运营要对照两页才能判断，且绑定但无成员行的账号仍会
  漏掉。
- **每次打开页面都实时拉取 new-api 账号列表**：会话有上限（默认 50），页面轮询会耗尽它；缓存
  由显式同步刷新即可。
