# 0006 管理账号可由环境变量预置

面板的管理账号除了首次运行表单创建外，还可以从环境变量预置：数据目录的 `.env`
（或 `QQBOT_ENV_FILE` 指定的文件）里的 `QQBOT_ADMIN_USERNAME` / `QQBOT_ADMIN_PASSWORD`，
进程环境变量优先于文件。

原因：无界面部署（容器、systemd、CI）里没人点首次运行表单，而且从进程启动到第一个管理员
创建之间存在一个窗口，先到达面板的人可以抢注账号。把凭据放在环境里，服务在**开始接受请求
之前**就把它建成/对齐，窗口消失。它同时是**密码丢失时的恢复路径**：改值、重启即重置。

约定与边界：

- **留空 = 不动已有账号。** `QQBOT_ADMIN_PASSWORD` 未设或只有空白时忽略，绝不把密码清空；
  模板里的空行因此无害。进程环境变量存在（哪怕为空）也会覆盖文件值——与 `LoadEnv` 的合并
  规则一致。
- **重复应用必须幂等。** 每次启动都跑这段逻辑；若密码与已存哈希一致就不重写，否则每次重启
  都会换一次哈希、进而作废所有会话（`auth.generation` 会因改密而自增）。
- **改密即吊销会话。** 值确实变了才 `bumpGeneration()`，规则与 WebUI 改密一致，泄漏的
  cookie 随之失效。
- **换用户名是新增而非替换。** 配置里的用户名与已有的不同时**新增**一个账号，不动原来的，
  这样名字打错也不会把管理员锁在门外。
- **权限。** 环境文件含明文密码，与 `config.yaml` 一样应设 `0600`，且不进版本库
  （`.gitignore` 已排除 `.env` / `.env.*`，只保留 `.env.example`）。
