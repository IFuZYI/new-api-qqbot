# 0002 绑定关系由本项目持有，new-api 只读

QQ 号与 new-api 账号的对应关系存在本项目自己的库里（`qq → newapi_user_id`），
new-api 只被调用其接口，本系统不写它的数据库、不改它的源码。

原因：new-api **没有任何管理员接口能改用户邮箱**。邮箱只在注册时（`register_enabled`
为 true 才可用）或用户自己的邮件绑定流程里写入，且全库 `LOWER(email)` 唯一。既然
「把 54321@qq.com 挂到某个账号上」无法通过接口表达，把映射放在本库就是唯一不越界的
做法：自动匹配只 **读**（`GET /api/user/search?keyword=54321@qq.com`），换绑只是改本库
一行。

代价与边界：
- 本系统的绑定与 new-api 的 email 字段可能不一致（管理员手动换绑后尤其如此）。以本库
  为准，new-api 的 email 只作为**自动匹配的线索**。
- 因为 new-api 的 email 唯一，同一个邮箱不可能对应两个账号；但一个 QQ 可能匹配到 0 个
  账号（→ 未绑定）或 1 个账号。搜到多个时按「精确等于 `qq@qq.com`」过滤，仍不唯一则
  不自动绑定，交管理员处理。
- 提升分组、发奖励走接口（`PUT /api/user/`、`POST /api/user/manage`），这些接口写的是
  new-api 自己的数据，属于正常调用，不算「直写数据库」。

被否决的替代方案：直写 new-api 数据库（绕过校验、审计与唯一约束，且随版本升级失效）；
或改 new-api 源码加管理接口（我们并不维护那套部署）。
