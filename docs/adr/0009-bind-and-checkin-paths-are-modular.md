# ADR-0009 — 绑定与签到按来源拆分，每条路径独立开关

状态：已采纳（2026-10-11）

## 背景

原实现把「怎么绑定」和「怎么算签到」都写死在代码里：绑定指令固定为 `>>绑定<<`，
签到只能来自 QQ 群自带的打卡榜轮询，且两条路径都跟着同一个「成员巡检」节奏跑。

运营侧提出了四类需求，它们指向同一个问题——**哪条路径算数，应该由运营决定，而不是由
代码决定**：

1. 绑定指令要可配置，支持多条、支持正则（不同群的习惯不一样）；
2. 成员进群就自动绑定；
3. 定期巡检自动绑定未绑定的成员；
4. 签到除了打卡榜，还要支持「发消息即签到」，同样支持可配置指令。

## 决策

**每条路径都是一个独立模块，有自己的开关和参数，默认值与原行为兼容。**

### 绑定：三条路径，一个决策点

`AutoBind`（巡检）、`BindMember`（进群）、`BindByCommand`（指令）全部走
`Service.bindQQ`。它先查绑定，已有绑定就直接返回「跳过」——**任何路径都不会改动已有
绑定**。这是让三个开关都能安全打开的前提：打开任何一个都不会覆盖管理员手工换绑的结果。

三条路径的区别只在触发方式和「查不到账号」的语义：

| 路径 | 触发 | 查不到账号时 |
|---|---|---|
| 巡检 `auto` | 周期（默认 60 分钟） | 计入 pending，下轮再试 |
| 进群 `join` | `group_increase` 事件 | 不算失败：人可能还没注册 |
| 指令 `command` | 群里发指令 | 报错（成员主动要求，应当有反馈路径） |

巡检与成员巡检拆开：绑定是「每个未绑定成员一次账号查询」，读名册是「拉取整份群成员
列表」，成本差一个数量级，没有理由绑在一起跑。

### 签到：(qq, 日期) 是唯一身份，来源只是属性

`checkins` 行仍然以 `(qq, 日期)` 为主键，新增 `source` 列（`board` / `message`）。
两条来源写同一行：

- 消息先到 → 建行（`source=message`），打卡榜后到 → **覆盖升级**为 `source=board`，
  并补上排名与打卡时间（打卡榜知道得更多）；
- 打卡榜先到 → 建行；此后的消息**不改动任何字段**（`RecordMessageCheckin` 只做插入，
  冲突即忽略）。

两条路径都不碰 `reward_quota` / `rewarded_at`，所以奖励的「每天每人一次」仍然只由
`ClaimReward` 的原子条件更新保证，来源数量与重复消息都无法影响它。

「任意消息都算签到」用**空指令列表**表示，而不是再加一个开关：`checkin_patterns` 为空
时没有消息会匹配失败，自然人人算签到。这避免了两处配置互相矛盾（开关说「任意」、
列表里却列着指令）。

## 被否决的方案

- **用消息事件完全替代打卡榜轮询**。事件流是可选的推送通道（见 ADR-0003），而打卡榜
  走的是 HTTP 动作通道，后者只要机器人可达就可用。让签到依赖事件流会把「有人签到却
  没拿到奖励」变成常态。两者并存，且互不覆盖。
- **给「任意消息」单独加一个布尔开关**。会与指令列表形成两个真相来源；空列表表达同一
  语义且不可自相矛盾。
- **把来源做成枚举并允许改绑**。来源是「这行是怎么来的」的记录，不是运营可选的设置。
- **把「关掉功能」只理解成「不执行动作」**。那样代码里仍会发请求：关掉打卡榜后循环照跑、
  照读榜单；规则只看 new-api 余额时仍读遍所有群成员列表。开关必须同时是**流量的开关**，
  否则「不使用对应功能时减少对 napcat 的频繁请求」这句话就是假的。
- **让发奖跟随打卡榜开关**。读榜与发奖是两件事：只开消息签到的运营仍需要发奖。把整条
  循环挂在打卡榜开关上会静默停发所有奖励。

## 后果

- `Settings` 新增 7 个字段，全部有默认值；旧的设置 blob 缺少这些字段时，解码进默认值
  即得到可用配置（`Settings` 先填默认值再 `GetSetting` 覆盖）。
- 正则非法时 `SaveSettings` 返回 400 而不是存下去：一个永远不匹配的指令是本功能最难
  被发现的故障。
- 事件监听器不再认识任何具体指令，只问服务「这条消息算不算指令」——所以改配置立即生效，
  无需重启。
- 新增 `GET /api/status`，把每条巡检的上次运行时间与错误连同开关一起返回：只看时间无法
  区分「还没跑」和「已停用」。
- `Rule.NeedsQQData` 决定一批规则是否需要读群成员列表；签到循环的间隔由「打卡榜巡检或
  消息签到」共同决定，读榜本身再单独按开关跳过。
