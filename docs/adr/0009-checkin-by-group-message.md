# 0009 打卡 = 在监测群发言，打卡榜轮询整体删除

打卡（check-in）的定义从「当天出现在群签到榜上」改为：**成员在任一监测群发出任意一条消息**。
文本、图片、表情，甚至 `>>绑定<<` 指令都算；不做任何过滤。签到榜（`get_group_signed_list`）
与整个轮询路径**已整体删除**，代码中不再有任何地方调用它。

原因：NapCat 没有签到事件（见 0003），榜单只含当日且分页，轮询要么频繁要么漏人；而「发言即打卡」
不需要榜单、不需要 rank，语义更简单、记录即时。这是产品所有者的明确决定：删除轮询，不保留
「以防万一」的旧路径。

## 由此产生的依赖与代价（明确接受）

- **事件 WebSocket 从「可选加速」变成打卡的必需依赖。** 打卡只从事件流来：流断开期间成员发的
  消息不会被记录，也就不会发奖（日志里 `[events] disconnected` 就是这个意思）。轮询回退被
  有意删除，不要为了「修复」断流把它加回来。
- **rank 不再记录。** 榜单的 `rank` 随榜单消失；`checkins.rank` 列保留，只服务于历史行。
- **机器人自己的消息**：本服务写入的 OneBot 适配器配置为 `reportSelfMessage: false`，NapCat
  不会推送机器人自己的消息；监听器不再按机器人 QQ 过滤（刻意不为此在每条消息上增加一次网络
  调用）。万一机器人消息到达，会多记一行签到——接受这个代价，因为漏记真实签到更糟。
- **发奖改为固定 1 分钟的独立循环。** 打卡即时到达，超过一分钟才发会像「打了卡没反应」；该
  周期不来自任何设置项。奖励仍按 `(qq, 日期)` 至多一次（见 0004）。
- **设置项 `checkin_patrol_enabled` / `checkin_sync_minutes` 删除。** 旧部署存量 JSON 里仍有这两个
  键：Go 的 json.Unmarshal 忽略未知字段，能正常加载，不需要迁移。

0003 中「群成员/群列表轮询」的论证仍然成立：成员与群仍由巡检重建，事件只是加速。被取代的
只是「打卡没有事件、只能靠轮询」这一半。
